## 1. 产品思维：从需求到解决方案

> **核心理念**：一个好的点子甚至大于好的技术。最近火爆的程序，从技术角度而言，大家在学习后都能够独立复现。

### 1.1 从想象到真实：学会向业务提问

#### 关键问题清单

在开始任何产品开发前，先问自己几个核心问题：

- **效率提升的具体含义是什么？**
  - 缩短上新时间？
  - 减少人力投入？
  - 提高商品详情页转化率？

- **当前流程的痛点在哪里？**
  - 团队每天需要上多少个新品？
  - 每个新品需要多少张图和多少字文案？
  - 现有工作流程中哪些环节最耗时、最痛苦？

#### 真实业务调研结果

**不要猜测，直接询问一线业务方**。通过深度访谈，我们获得了抖音电商运营的真实痛点：

**管理店铺多、任务杂：**
- 运营需要同时管理多个店铺、多个商品，处于不同阶段推进
- 每天在"上新、改价格、调素材、看投放数据"之间频繁切换
- 内容生产更像是"在既有素材基础上快速试错"的过程

**具体工作流程：**
1. 先用厂家图包、历史素材或市场样板，快速挂上架
2. 通过投少量流量、做简单活动，观察基础转化
3. 只有跑出数据的商品，才投入精力做深度优化

> **重要提醒**：不要试图"一口气满足所有诉求"，产品会变得庞大且难以落地。需要进一步梳理和收敛，找出真正的核心痛点。

### 1.2 从发散到收敛：锁定核心痛点

#### 问题分类与优先级

通过调研发现的问题可以归纳为三类：

1. **运营节奏问题** - 上新/调价/上架节奏
2. **工作台问题** - 多店多品整体效率  
3. **内容生产问题** - 为商品快速产出图片和文案

**最佳选择：优先解决内容生产问题** - 最适合课堂时间和难度控制。

#### 业务方核心痛点

**痛点一：批量制作普通商品首版图文耗时耗力**
- 素材分散在网盘、聊天记录、平台后台
- 厂家图、历史素材、竞品截图混杂管理
- 上新多为批量推进，只能拼凑主图和标题卖点
- 核心诉求是"能上架、不太丑"的基础内容

**痛点二：优质图文结构难以系统化复用**
- 有效方案散落在大脑、聊天记录、历史商品链接中
- 复用需反复翻旧链接、复制替换参数，流程繁琐
- 缺少可收藏、管理、直接套用的沉淀工具

#### 产品定位

**最终收敛为简单清晰的小应用：**
> 给多店多品抖音运营用的「批量图文草稿机 + 个人模板库」

**只做两件事：**

**功能一：帮运营批量生成第一版图文草稿**

**输入支持：**
- 商品基础信息：名称、类目、品牌、材质、尺寸、颜色、适用人群等
- 商品图片：白底图/简单场景图
- 支持上传历史爆款截图或参考链接
- 支持Excel批量导入或页面在线录入
- 可选择保存商品素材到素材库

**输出内容：**
- 每个商品一张"看得过去、包含基础卖点"的主图草稿
- 一条"结构合理、含核心关键词"的标题 + 1-2句卖点文案

**使用方式变化：**
从每批商品白手起稿 → 把商品丢进系统，拿生成的草稿做筛选和微调

**功能二：把好用的输出沉淀成可复用的模板库**

**收藏内容：**
- 任意"好用"的输出都可以一键收藏
- 可以是完整组合，也可以是标题结构、卖点文案等部分

**收藏后功能：**
- **复用**：套新商品参数重新生成草稿，或做A/B测试
- **编辑**：修改文案，微调图片元素
- **管理**：命名、打标签、按店铺分类，方便检索

**下次使用：**
导入新商品后，可选择系统默认生成或使用收藏模板自动生成

> **产品思维总结**：不要被需求表象迷惑，不要试图一口气做大做全。通过提问、拆解、收敛，找到既能解决真实痛点、又能在有限时间内落地的最小可行方案。

## 2. 快速原型：10分钟产出可运行产品

> **核心理念**：Thinking是好事，但不可over thinking。从单个页面开始制作原型。

### 2.1 第一步：用大白话告诉AI你要什么

#### 方法一：直接让AI生成

**提示词模板：**
```
帮我参考业务逻辑实现一个单页面应用，用来验证核心玩法功能，包括：
1. 帮运营批量生成第一版图文草稿；
2. 把好用的输出沉淀成可复用的模板库。

由于第一个更重要，你可以先生成第一个的内容。

业务逻辑参考如下：
[此处粘贴详细业务逻辑]
```

#### 方法二：让AI生成"生成程序"的提示词

**更高级的做法**：让AI基于需求生成专门给coding Agent的提示词

**提示词结构：**
```
基于下面的想法和内容，帮我写一个发给coding Agent的写代码用的提示词：

我想参考业务逻辑实现一个单页面应用，用来验证核心玩法功能，包括：
1. 帮运营批量生成第一版图文草稿；
2. 把好用的输出沉淀成可复用的模板库。

业务逻辑参考如下：
[详细业务逻辑]
```

### 2.2 第二步：让AI IDE直接生成代码

**操作流程：**
1. 获得初始提示词
2. 创建项目文件夹
3. 打开AI IDE，粘贴提示词
4. 等待代码生成完成

### 2.3 第三步：处理报错和调试

#### 常见报错处理方案

**方式一：页面或终端报错**
- 页面变红、白屏，或终端出现红字
- **解决方案**：直接截图或复制全部错误信息发给AI

**方式二：功能不对但没报错**
- 按钮没反应、数据没显示、样式乱了
- **解决方案**：用大白话描述"现在发生了什么 + 你本来想要什么"，必要时加截图

**方式三：不确定有没有问题**
- **解决方案**：直接问AI"帮我检查一下这个功能有没有明显问题，需不需要调整"

#### 新手常见疑问解答

**Q：不知道错误信息在哪里？**
A：看所有"红色的字"。在终端、控制台或页面找到红色提示，全选复制给AI。

**Q：AI改完还是报同样的错怎么办？**
A：常见情况。继续截图或复制最新错误信息发给AI，让它在上次修改基础上进一步修复。

**Q：需要完全理解AI的修复方案吗？**
A：不需要一次性全部搞懂。每次只关注一两个点，久而久之会逐渐看懂越来越多代码。

**Q：改了很多次问题还是没解决怎么办？**
A：可以尝试：
- 使用IDE的"版本回退"功能，回到可运行版本重新开始
- 更换模型或调整提示词，将现象、错误信息讲得更具体
- 将"当前代码 + 错误日志 + 预期行为"打包，一次性发给AI整体重构

## 3. 功能完善：从单页面到多页面应用

当核心玩法逻辑基本生成完毕后，需要扩展剩余功能：

**常见待完善功能：**
- 设置页面
- 模板管理页面
- 用户账户相关功能

**处理方式：**
- 让AI根据业务提示词需求检查，生成未实现部分
- 直接指定某个页面让AI补充
- 逐步完善所有功能模块

## 4. 体验优化：让原型更加专业

**最终目标**：从"能跑"变成"用起来顺手、看上去专业"

**优化方法：**
1. **全流程体验**：动手体验一遍完整用户流程
2. **问题修复**：让AI修复无法运行的部分
3. **反复测试**：每次刷新后从零开始模仿新用户走完全流程

**测试数据准备：**
为了避免每次测试都手动新建数据，可以让AI生成测试数据入口：

**提示词示例：**
```
我现在需要测试这个用户使用过程，确保他能完全走通，请你结合下列需求生成测试数据入口，让我能够点击后很快测试全流程是否正常：

[粘贴具体功能需求]
```

**AI一般会输出：**
- 测试用例清单
- 快速数据生成按钮
- 自动化测试建议

## 📋 学习要点总结

### 核心方法论
1. **从真实业务出发**：深度调研，不要猜测
2. **聚焦核心痛点**：不要试图一次性解决所有问题
3. **快速原型验证**：用AI辅助快速生成可运行产品
4. **迭代优化**：基于用户反馈持续改进

### 关键技能
- 业务需求分析和收敛能力
- AI提示词编写技巧
- 快速原型开发能力
- 问题调试和解决能力

### 实践建议
- 保持与业务方的持续沟通
- 记录每个版本的改进点
- 建立测试数据体系
- 关注用户体验细节

> **最终目标**：掌握从业务需求到产品原型的完整闭环能力，为后续接入AI能力打下坚实基础。
